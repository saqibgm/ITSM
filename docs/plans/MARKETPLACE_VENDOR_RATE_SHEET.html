Vendor Rate Sheet · Commerce Messaging & OMS Researched Sept 2026

What the marketplace-integration market actually charges

Three categories, priced separately: helpdesk bridges that carry buyer messages, unified APIs meant to be embedded into a product like ours, and seller-facing platforms a business runs on its own. They solve different problems and shouldn't be shopped against each other.

Every figure below came from a vendor's own pricing page or a review aggregator that cites one — not an estimate. Where a vendor hides its real number behind a sales call, that's marked rather than guessed at.

Read on it

For the actual messaging gap, all four vendors were checked directly. eDesk is the only one with a real, documented API — and it's paywalled to a custom-quoted Enterprise tier. ChannelReply, Replyco, and ReplyDesk have no confirmed API at all — they're web-app-only helpdesks with integration setup guides for pulling marketplace data in, not a documented way to build against their data. That collapses this category to one real option, and its price is unknown until a sales call happens.

The other two tables tell the opposite story: API access is nearly universal — every vendor across both has a confirmed, documented developer API except Codisto (not a standalone product). API2Cart and Apideck stand out as the purest cases: no UI product at all, the API is the offering, and both publish a fully transparent rate card down to the entry tier — rare in this sheet. But none of the 15 vendors across these two tables read or send a buyer message. Architecturally, the unified-API table is the closer analog to what itsm-service would actually integrate against — but it still doesn't close the messaging gap, it just closes a different one.

Worth flagging specifically: Anchanto has pre-built connectors to Shopee, Lazada, and TikTok Shop by name — directly relevant given the Shopee connector already shipped this session — but it's fully sales-gated with no public number at all, and (like the rest of this table) has no confirmed messaging capability either.

Net effect: the messaging gap and the API-access gap are the same problem. Nothing in this sheet is a documented, API-driven, publicly-priced messaging bridge — that combination doesn't exist in this market. The next real step is the eDesk Enterprise sales conversation, or a direct question to ChannelReply/Replyco/ReplyDesk asking outright whether an undocumented/partner-only API exists that their public docs don't show.
